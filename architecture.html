Arquitectura

Arquitectura técnica y diagramas

Núcleo de dominio puro, adaptadores intercambiables y despliegue serverless en AWS us-east-1, descrito como código con Terraform.

Arquitectura hexagonal

Los repositorios de backend separan tres capas. El mismo núcleo se ejecuta en un servidor local y en AWS Lambda; no hay una segunda implementación de la política "para Lambda".

core

Dominio puro: sin boto3, HTTP ni frameworks. Los puertos son typing.Protocol. Un test (test_core_purity.py) lo verifica.

adapters

DynamoDB, Bedrock, Secrets Manager, API Gateway Management API, EventBridge Scheduler y versiones en memoria.

interfaces

Transporte: handler de Lambda (HTTP API v2 y WebSocket) y servidores locales (FastAPI en api; local_server en communications).

Decisión clave: la Lambda valida el JWT; API Gateway solo enruta (no hay aws_apigatewayv2_authorizer). Una sola implementación de la política evita divergencias silenciosas.

En el teléfono de quien recibe: lectura por voz en cada cambio de nivel; vibración y alarma sonora únicamente en rojo. El aviso a la Red de Confianza es manual: un toque en el botón «Avisar» envía el POST /notifications.

Las transiciones de la llamada son condicionales en DynamoDB: gana el primer escritor. Las reglas duras (desafio_fallido, dinero_mas_urgencia, clonacion_vocal, suplantacion_biometrica) fuerzan RED con score 100.

Además existen profiles y challenges (módulo data) y las tablas de conexiones de avisos y de monitoreo. Las transcripciones y el audio no se guardan.
